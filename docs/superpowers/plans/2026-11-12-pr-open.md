# pr-open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `pr-open` skill that takes a finished branch to an open, review-ready GitHub PR (issue #36), and replaces the `pr-preparer` agent.

**Architecture:** A thin Node engine (`shared/pr-open/scripts/main.mjs`, behind a POSIX `sh` shim like `pr-respond`) does every step a script can check: command detection, the test run and its counts, the signed and AI-mention checks, the secret scan, the parent marker, and `gh pr create`. `SKILL.md` tells the agent to do the judgment steps: format and lint, the history plan, the PR body text, and the handoff. The engine imports the secret scan from `shared/pr-review/scripts/lib/secrets.mjs`; it does not touch `pr-review/scripts/main.mjs` (that file has open edits on `feat/pr-respond`).

**Tech Stack:** Node 24 stdlib only, `node:test`, POSIX `sh`, `git`, `gh` CLI; optional `secret-scan` (#39) and `gitleaks`.

**Spec:** GitHub issue #36 (`gh issue view 36`), plus the decisions below. Read both.

## Decisions (from the user, 2026-11-12)

1. Form: thin engine + `SKILL.md`.
2. Stacked PR: the PR base is the parent branch, and the body carries `<!-- pr-open parent: <branch> -->`. `pr-land` reads the marker. Rule (changed after review): a non-default base with an open PR is a stack; a non-default base with no open PR is a plain base, and `open` warns `<base> has no open PR: opened as a plain base, no parent marker`.
3. History: the agent proposes the new commit plan, the user approves, then the agent rewrites. Backup ref first.
4. Commands: detect from project files, with an override; ask the user when nothing is found.
5. Secrets: call `secret-scan` when it is on PATH, else `scanOutbound` from `pr-review`.
6. The PR opens ready for review; `--draft` opens a draft.
7. Handoff: ask each time — `pr-review` round, `pr-respond`, or stop.
8. Delete `~/.claude/agents/pr-preparer.md` (a plain file; no nix-darwin source found).

## Global Constraints

- No npm dependencies. Tests: `node --test shared/pr-open/scripts/test/*.test.mjs`.
- Every command prints one JSON object on stdout. Exit codes: `0` done, `1` usage or setup error, `2` blocked by a check (unsigned commit, AI mention, secret, no test record, failed tests), `4` an external command failed (`git`, `gh`).
- `gh` goes through `process.env.GH_BIN || "gh"`, so tests use the stub `shared/pr-review/scripts/test/gh-stub.mjs`.
- Never print a secret: hits are `<rule>: <first 4 chars>…`, as `scanOutbound` does.
- Never force-push a branch that already has an open PR. Never merge.
- Prose in `SKILL.md`, the PR body and messages follows `shared/pr-review/writing.md`.

## Review Focus

1. Tests run on a dirty tree: the record would claim a sha that was not what ran. Expect exit `2`, no record. (Task 2)
2. The branch was pushed, then rewritten, and has no PR yet: `open` must push with `--force-with-lease`, not plain push, and never force when a PR is open. (Task 4)
3. A word like "Copilot" is part of the repo's own subject (this repo has a `pr-respond` that talks to Copilot): the AI check must allow it through `.pr-open.json` `allow`, not silently skip the whole check. (Task 3)
4. The base has no open PR, or is the default branch: a non-default base with no PR is a plain base with a warning (see Decision 2); `--base main` is not a stack and gets no marker. (Task 4)
5. HEAD moved after `pr-open test` (a new commit, or a rewrite): the record for the old sha must not count. Expect exit `2`, "run pr-open test again". (Task 4)

### Task 1: Command detection

**Files:**
- Create: `shared/pr-open/scripts/lib/detect.mjs`
- Test: `shared/pr-open/scripts/test/detect.test.mjs`

**Interfaces:**
- Produces: `detect(dir: string, env = process.env) -> { format: string|null, lint: string|null, test: string|null, source: {format, lint, test} }` where each `source` is `"env" | ".pr-open.json" | "package.json" | "Makefile" | "justfile" | "Cargo.toml" | "go.mod" | null`.
- Produces: `readOverride(dir) -> { format?, lint?, test?, allow?: string[] }` (empty object when `.pr-open.json` is missing; throws `Error("bad .pr-open.json: …")` on invalid JSON).

Order per key, first hit wins: env `PR_OPEN_FORMAT` / `PR_OPEN_LINT` / `PR_OPEN_TEST` → `.pr-open.json` → `package.json` scripts (`format` or `fmt`; `lint`; `test`, run as `npm run <name>`, or `pnpm`/`yarn`/`bun` when its lockfile is there) → `Makefile` targets (`fmt` or `format`; `lint`; `test`) as `make <t>` → `justfile` recipes, same names, as `just <t>` → `Cargo.toml`: `cargo fmt`, `cargo clippy -- -D warnings`, `cargo test` → `go.mod`: `gofmt -w .`, `go vet ./...`, `go test ./...`. `CLAUDE.md`/`AGENTS.md` are for the agent (Task 5), not this function.

### Task 2: Test run and counts

**Files:**

- Test: `shared/pr-open/scripts/test/counts.test.mjs`

**Interfaces:**
- Produces: `parseCounts(output: string) -> { passed: number, failed: number, skipped: number } | null`.
- Produces: `runTests(dir: string, command: string) -> Promise<{ sha, command, exit, counts, at }>`. It streams the output to stderr, writes the record to `<git-dir>/pr-open/tests-<sha>.json` (`git rev-parse --git-dir`, so each worktree has its own), and returns it.

Formats to parse (take the last match in the output; sum when a runner prints several summaries, as `cargo test` does per crate):

| Runner | Line |
|---|---|
| node --test | `ℹ pass 416`, `ℹ fail 0`, `ℹ skipped 1` (also `# pass` TAP form) |
| jest | `Tests:       1 failed, 2 skipped, 40 passed, 43 total` |
| vitest | `Tests  40 passed \| 1 failed \| 2 skipped (43)` |
| pytest | `=== 40 passed, 1 failed, 2 skipped in 1.2s ===` |
| cargo | `test result: ok. 40 passed; 0 failed; 2 ignored;` (ignored → skipped) |
| go test -v | count `--- PASS:`, `--- FAIL:`, `--- SKIP:` lines |

### Task 4: Open the PR, with the parent marker

**Files:**
- Create: `shared/pr-open/scripts/lib/open.mjs`
- Test: `shared/pr-open/scripts/test/open.test.mjs`

**Interfaces:**
- Consumes: `readRecord` (Task 2), `checkBranch` (Task 3), `readOverride` (Task 1), `scanOutbound` from `../../../pr-review/scripts/lib/secrets.mjs`.
- Produces: `PARENT_MARKER = "<!-- pr-open parent: "`; `parentOf(body: string) -> string|null` (for `pr-land`, #40).
- Produces: `buildBody({ body, record, parent, parentPr }) -> string`. It appends a `## Tests` line generated from the record, `` `<command>` at <sha7>: <passed> passed, <failed> failed, <skipped> skipped. ``, replacing any earlier `## Tests` section the agent wrote. For a stack it adds `Stacked on #<parentPr>.` as the first line and the marker `<!-- pr-open parent: <branch> -->` as the last line.
- Produces: `openPr(dir, { title, bodyFile, base, draft = false }) -> Promise<{ url, number, base, parent: string|null, warnings: string[] }>`.

`openPr` order (stop at the first failure):
1. Repo default branch: `gh repo view --json defaultBranchRef`. `base` defaults to it. `parent = base === default ? null : base`.
2. A stack needs the parent's open PR: `gh pr list --head <parent> --state open --json number`. None: `Usage("open a PR for <parent> first")`.
3. This branch already has an open PR (`gh pr list --head <branch> --state open --json number,url`): return it with `warnings: ["a PR is already open"]`; do not push.
4. `readRecord(dir, HEAD)`: missing → `Blocked("no test run for <sha7>: run pr-open test")`; `exit !== 0` or `counts.failed > 0` → `Blocked("tests failed at <sha7>")`. `counts === null` is allowed: the line says `counts not found in the output` and a warning is added.
5. `checkBranch(dir, "origin/" + base, { title, body, allow })`: not ok → `Blocked` with the JSON of the result (no secret in it).
6. Secret scan of `git diff origin/<base>...HEAD` + title + body: if `secret-scan` is on PATH, pipe the text to `secret-scan` on stdin (exit 0 clean, any other exit is a hit; pass its stderr through). Else `scanOutbound(text)`. A hit → `Blocked` with the masked hits.
7. Body without `#<n>`: add warning `"no linked issue"`.
8. Push: `git push -u origin HEAD --force-with-lease` (no PR is open here, by step 3, so a rewrite before the first PR is allowed).
9. `gh pr create --base <base> --head <branch> --title <title> --body-file <tmp> [--draft]`; parse the URL from stdout, the number from the URL.

`main(argv) -> Promise<exitCode>`, exported for tests; the module runs `process.exit(await main(process.argv.slice(2)))` only when it is the entry file. Errors map to exit codes per Global Constraints.

`SKILL.md` (frontmatter `name: pr-open`, a description with the triggers "pr-open", "open a PR", "ship this branch", "prepare a PR") says, in order:

1. Base: the default branch, or a parent branch for a stack (ask when the branch is not based on the default branch and the user did not say).
2. Run `pr-open detect`. A null command: look in `CLAUDE.md`/`AGENTS.md`/`CONTRIBUTING.md`; still none, ask the user. Run format, then lint; fix what lint reports.
3. Plan the history: list the new commits (groups and concise messages in the repo style, no AI or tool names). Show it to the user and wait for a yes. Then `git update-ref refs/pr-open/backup/<branch> HEAD`, rewrite, and sign every commit (`git commit -S`). The user can say "keep the history".
4. `pr-open test`. Fix failures; any new commit means run it again.
5. Write the body from `git diff origin/<base>...HEAD`: what changed, why, how it was tested (no numbers: the engine adds the `## Tests` line), breaking changes, and `Closes #N` or the checklist item it covers. Then `pr-open check`, then `pr-open open`.
6. Ask: start a `pr-review` round, start `pr-respond`, or stop.

Rules: never write test numbers by hand; never force-push a branch with an open PR; never merge; a hit from `check` or the secret scan is fixed, not worked around (an AI-tool word that is the subject of the repo goes in `.pr-open.json` `allow`, after the user says yes).
