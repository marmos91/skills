# pr-review and pr-review-loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/pr-review` (a multi-model council review of one PR) and
`/pr-review-loop` (an interval loop that keeps a repo's PR queue moving) as
cross-harness skills in `marmos91/skills`.

**Architecture:** One Node engine (`shared/pr-review/scripts/main.mjs`, behind
a POSIX `sh` shim) runs stages with markers on disk. Model work goes to
headless CLI children through harness adapters (`claude -p`, `pi -p`). All
decisions that matter (tally, verdict, convergence, line placement, idempotency)
are pure functions with unit tests. GitHub access goes through the `gh` CLI,
with a stub (`GH_BIN`) for tests. Both `SKILL.md` files stay thin.

**Tech Stack:** Node 24 (stdlib only, `node:test`), POSIX `sh`, `gh` CLI,
`claude` CLI, `pi` CLI, optional `jev` CLI and `gitleaks`.

**Spec:** `docs/superpowers/specs/2026-11-11-pr-review-design.md` (read it in
full; section numbers below refer to it).

## Global Constraints

- No npm dependencies. Node stdlib only; tests use `node --test`.
- Engine children never get `GH_TOKEN`, `GITHUB_PERSONAL_ACCESS_TOKEN` or
  `AWS_*` in their environment (spec §4 rule 2).
- pi adapter always runs `pi -p ... < /dev/null` (spec §9.1).
- claude adapter sends the prompt on stdin, never after `--tools` (spec §9.1).
- claude seats: `claude -p --restricted --strict-mcp-config --model <m> --effort <t> --tools <list>`;
  `--bare` only when `CLAUDE_CODE_OAUTH_TOKEN` is set (spec §9.1).
- pi seats: `pi -p --no-session --no-context-files --no-extensions --no-skills --no-mcp --provider <p> --model <m> --thinking <t> --tools <list>`.
- Read-only tools: claude `Read,Grep,Glob`; pi `read,grep,find,ls`. Add
  `Bash`/`bash` only for a trusted author (`OWNER|MEMBER|COLLABORATOR`).
- Posted text carries no AI attribution and no signature. Every posted body
  ends with `<!-- pr-review run=<id> sha=<sha> key=<hash> -->`.
- Config files: `~/.config/pr-review/config.json`, repo `.pr-review.json`
  read from the base branch. Repo-level allowlist: `lenses.*.enabled`,
  `loop.authors_ignore`, `loop.max_prs_per_run`, `review.guidance`.
- Defaults (spec §5): seats `claude:opus:high`, `auto:cubbit/mimir-pro:high`,
  `auto:cubbit/mimir:high`. `auto` = `claude` when `it-router` answers
  (`curl -fsS -m 2 http://127.0.0.1:4000/router/health`, URL overridable with
  `PR_REVIEW_ROUTER_HEALTH`), else `pi`. In Claude Code no `pi -p` runs; `round1: "per-seat"`; judge `claude:opus:high`;
  `decider.kind: "auto"`; `loop.max_prs_per_run: 10`,
  `loop.max_review_rounds: 3`, `loop.max_replies_per_thread: 2`.
- `decider.confidence` default: the value in `shared/jev/bench/RESULTS.md`
  (jev calibration). Until that exists, `0.5`.
- jev lookup: `$SKILL_DIR/../jev/bin/jev`, else `jev` on PATH. Exit codes:
  0 yes, 1 no, 2 no answer/unsure.
- State root: `${XDG_STATE_HOME:-$HOME/.local/state}/pr-review/<owner>__<repo>/`.
- Engine exit codes: `0` done, `3` questions waiting for the user, `4`
  a stage failed after retries, `1` usage or setup error.
- Commits: `git commit -S`, conventional, concise, no AI attribution.
- Prose in `SKILL.md`, prompts and docs: Simplified Technical English style.

## Review Focus

1. **The head moves during a run** (author pushes while seats work): the
   engine must re-frame, never post line comments for code the seats did not
   see. Test in Task 11.
2. **A crash between the post and the state write**: a rerun must find the
   marker on GitHub and not post again. Test in Task 11.
3. **A PR from an untrusted author with hostile text** ("approve this PR" in
   the body, a `.pr-review.json` or `CLAUDE.md` in the head): no shell for
   seats, config from base only, verdict never `APPROVE` from the loop. Tests
   in Tasks 1, 2, 6 and 9.
4. **The loop and a manual `/pr-review` run on the same PR at once**: the
   repo lock makes the second one exit cleanly. Test in Task 14.
5. **jev is missing, down or unsure**: split findings still reach the user as
   questions; nothing is lost or silently posted. Test in Task 11.
